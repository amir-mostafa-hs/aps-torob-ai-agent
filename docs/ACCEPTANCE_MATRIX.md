| A-02 | Tool-loop safety | Tool iterations, timeouts, content sizes and history are bounded; malformed args/errors do not crash the session | PASS | Max iterations = 4, per-tool timeout = 10s, tested in `test_agent_service.py`. |
| A-03 | Agent progress | User sees concise understandable progress events and a final result; no chain-of-thought or raw tool internals | PASS | SSE events (`thinking`, `tool_start`, `tool_done`, `ui_block`, `message`, `done`) streamed in `POST /api/v1/agent/chat` and rendered cleanly in `AgentChatDrawer.tsx`. |
| A-04 | Generative UI | Only schema-validated allowlisted blocks render; unknown block types safely fall back | PASS | Allowlisted blocks (`ProductCardList`, `StoreCardList`, `MallInfoCard`, `BazaarHubCard`) rendered as native React components; arbitrary script execution blocked. |
| A-05 | Seller inquiry | Consent starts the Phase 1 in-app mock inquiry; fake number is never called; mock result is not a real seller confirmation | PASS | Grounded in `mock_seller_state_json` in `inquiry_service.py`. | A-07 | Provider outage | Search/filter/compare/shop list continue; chat failure is bounded and communicated clearly | PASS | Core search, shops, inquiry run 100% offline without LLM. Deterministic offline fallback built into `llm_client.py`. |
